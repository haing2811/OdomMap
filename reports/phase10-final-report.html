What was built

A static, single-page tool with no build step, no npm dependencies, no CDN, and no external fonts — fully offline PWA. It works at the site root and under /odom-map/.

  • Measure mode — two-click line measurement: distance (mm), acute reference angle, wheel rotations/degrees, H/V components, edge-to-point distance.
  • Odometry mode — origin placement, snapped 0/90/180/‑90 angle indicator, rotated axes, X/Y/angle/distance readout, Record → Python (x, y) tuple output, Copy to clipboard.
  • Route mode — place waypoints, drag nodes, delete selected node (Escape cancels), save/load/unload routes.
  • Field selection → competition → year → category, remembered and reflected in the URL (?c=wro&y=2026&cat=elementary).
  • Storage — v2 namespaced localStorage keys (odom:v2:), idempotent v1 migration, wheel/grid/last-selection globals.
  • PWA — service worker odommap-v4, network-first HTML, cache-first assets, field images cached at runtime; installable.

Math verified: 5/5 WRO samples match HEAD exactly; ENJOY AI 1000 mm horizontal/vertical/corners verified against a Node harness.

Blocked — browser-based checks (Phase 3, could not run)

Headless Chrome and Edge cannot run in this sandbox. Six launch approaches were attempted, all failing:

  • --headless=new --disable-gpu --dump-dom over localhost — hangs (exit 124 = timeout).
  • --headless=old --disable-gpu --no-sandbox over file:// — GPU process crashes (exit_code=-1073741819, STATUS_ACCESS_VIOLATION), then hangs.
  • --single-process --no-sandbox --disable-gpu — hangs on updater named-pipe loop.
  • Fresh --user-data-dir + --no-first-run --no-default-browser-check — same GPU crash + hang.
  • --disable-background-networking --disable-features=UpdateService --no-check-update — still hangs.
  • Edge msedge.exe --headless=new — same GPU/network-service crash, hangs.

Root cause: this sandbox breaks Chrome's GPU subprocess and the Chrome updater named-pipe connection, which retry indefinitely and keep the process alive. No command-line flag combination avoided it. This is an environment limitation, not an app defect.

Guesses & assumptions made during the build

  • WRO fields: image aspect (18599×9000 ≈ 2.0666) equals field aspect (2362/1143 ≈ 2.0665), so one shared scale is exact for WRO.
  • ENJOY AI: separate x/y scales because image aspect (1823×1022 ≈ 1.7838) differs from field aspect (2160/1200 = 1.8000).
  • v1 routes stored in canvas pixels without the save-time scale cannot be reliably back-converted—imported as approximate at current scale, flagged in the UI/data.
  • OdomMap.html kept as a thin client-side redirect rather than removed.
  • Image border-frame calibration (imageBoundsPx) intentionally left uncalibrated (TODO in config.js).
  • No start box, no robot customization, no HyperLib link—per product decision.
  • Angle-of-change feature is absent in HEAD and was flagged, not built.
